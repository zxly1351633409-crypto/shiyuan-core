# 给公司 Codex：仅在用户明确选择公司离线模式时安装

> 这不是公开模板的默认安装入口。普通个人电脑请返回仓库根目录，阅读
> START_HERE_CODEX.md 并运行根目录 install.ps1。

只有当用户明确要求公司安全模式时，才视为授权在当前公司电脑上检查并安装
此目录。仅仅打开或克隆仓库，不构成安装公司模式的授权。

此授权不允许你绕过公司制度、终端安全策略、管理员限制或权限提示。如果公司政策不允许本地 Hook/MCP/插件，或当前环境不给你写入用户配置的权限，请停止并清楚报告阻塞，不要尝试规避。

## 目标

- 让本机 Codex 使用十元完整已确认抽象记忆快照与公司安全规则。
- 启用公司本地的短候选提取、人工审核、已确认记忆召回和可见对话归档；凭据落盘前脱敏。
- 如果本机存在 Hanako，同时安装 Hana Hook；不存在则不要额外安装 Hanako。
- 不连接家庭服务、私人消息网关或任何未获组织许可的外部系统。
- 不自动上传、复制或汇总当前公司的文件与对话；只有你明确生成并人工审核的抽象交接卡才可进入交接箱。

## 请自行执行

1. 阅读 `README.md`、`SECURITY.md`、`company-policy.md`、`confirmed-memory.md`、`install.ps1` 和 `verify-package.ps1`。
2. 运行 `verify-package.ps1`，确认内容清单与 SHA-256 全部通过。
3. 检查 `install.ps1` 只修改当前用户目录，并会备份现有 Codex 配置。
4. 检查 Python 3.10+ 是否可用。
5. 若本机有 `%USERPROFILE%\.hanako`，运行 `powershell -ExecutionPolicy Bypass -File .\install.ps1`；否则运行 `powershell -ExecutionPolicy Bypass -File .\install.ps1 -Codex`。
6. 阅读 `%USERPROFILE%\.shiyuan-company\INSTALL_REPORT.md`，核验 `.codex\config.toml` 中只有一组 `BEGIN/END SHIYUAN_COMPANY_SAFE` 配置块。
7. 用隔离测试句“我喜欢先看验证证据。”检查只产生一条 candidate；再检查问题句与常见密钥样式不会产生 candidate。不要使用真实公司资料做测试。
8. 报告实际安装了哪些身体、配置备份位置、验证证据和任何未完成项。
9. 新会话中检查“公司本地知情范围与新鲜度”，确认它只显示元数据，并明确未接入内容仍未知。

## 验收边界

- 当前会话不会因为修改配置而自动获得新 Hook；安装完成后应请用户重启 Codex/Hanako，并新建一次会话。
- 新会话应能说明自己处于公司安全离线模式，读取完整已确认记忆快照，并在最终回复末尾显示 `🐳 十元·公司安全模式`。
- 新会话应能列出、确认、拒绝和召回公司本地短候选；Codex 与 Hana 同时安装时应读取同一目录。
- 工作型新会话开始后，Codex 的用户可见阶段更新应自动出现在公司本地最近工作检查点；不得出现 reasoning、工具调用或工具原始输出。
- 新会话应能区分活跃工作与过期残留，并列出本机已接入的可见历史来源；不得包含对话正文、文件路径或凭据。
- 不能因为看到了静态快照，就声称家庭 Core 在线或已经完成跨电脑实时同步。

如果需要回滚，请先阅读并运行 `uninstall.ps1`。它会归档组件和配置备份，不直接删除交接箱内容。
